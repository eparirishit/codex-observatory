How to read this Measurement notes 1–10
  1. Tokens and allowance. Cached input is part of input; reasoning is part of output. The composition chart splits cached input, fresh input, and generated output without overlap. Missing counters show as —. Recorded tokens measure activity, not subscription quota; exact subscription charges, per-tool token costs, and plugin instruction overhead remain unavailable. API-equivalent estimates are separate (note 8).
  2. Repeat candidates. A candidate repeats the same tool and arguments in the same turn after a recorded failure. Known overlapping executions are excluded. This is a heuristic, not proof of a retry or avoidable work; successful polling is not flagged.
  3. Timing. Calls can overlap, so recorded durations cannot be added to obtain wall time. A wrapper returning establishes that output arrived, not that an inner execution succeeded.
  4. Accounting. Response records are preferred and deduplicated by response ID; snapshots are not added again. Older cumulative deltas can combine responses and approximate turn attribution. An inherited initial baseline is excluded. Matching session segments are merged; parent totals exclude child sessions. Outer model calls and inner executions remain separate layers.
  5. Context proxy. Response input includes instructions, history, files, and tool definitions. It approximates context size but does not measure exact live occupancy or isolate any source’s token contribution. Cumulative input is not context size.
  6. Account snapshots. Percentages and reset times are historical account-level observations, potentially including other chats or cloud work. Stale observations are marked; percentages must not be summed across sessions or buckets.
  7. Coverage. Compactions count committed checkpoints, excluding mirrored items. Coverage warnings identify unreadable, partial, or unsupported records. Activity absent from local logs remains unobserved.
  8. API-equivalent cost, not subscription charges. Dollar estimates use the catalog dated 2026-10-30 or your local overrides. Cached input and reasoning are not counted twice. Published long-context adjustments apply per response. Unknown models, unknown recorded tiers, missing counters, or cache writes without a known retention rate remain unpriced. A partial subtotal covers priced responses only. Scenario selectors apply the chosen API tier to every response; they do not change Codex or infer past subscription charges. Regional premiums and separate tool/service fees are excluded.
  9. Context change after tools. This is the signed change in input between consecutive logged responses in the same turn. It also includes assistant output and other context changes, so it is not a tool’s token cost. Intervals with multiple executions stay shared; compaction and model/effort changes suppress the proxy.
  10. Rates, windows, and projects. Tokens per execution and per turn-minute describe activity, not productivity. Reasoning share does not score answer quality. Calendar groups use recorded response times in your browser’s time zone, with Monday-start weeks. Window rows show local observed activity inside recorded account windows; account percentage slopes can include other activity and are not token-to-quota conversions. Raw working directories never reach the browser. Project labels and price overrides are stored only in this browser and excluded from metrics exports.

Coverage & privacy

The reader opens session logs and selected configuration fields read-only. Prompts, reasoning text, commands, arguments, outputs, file paths, account IDs, credentials, and environment variables are excluded. No database, external assets, or outbound API calls. Only your project labels and pricing preferences are stored in this browser; access tokens remain in tab memory. Exports contain anonymous IDs, timestamps, model/tool names, and counts.
